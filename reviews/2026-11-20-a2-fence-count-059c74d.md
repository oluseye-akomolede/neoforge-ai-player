## F1 — a non-js block still inflates `closed`, and can still hide a missing js close

`closes` counts **every** bare fence line, so a non-js block contributes both its opening
fence (which is alone on its line when untagged) and its closing fence. Executed at the rev:

| Reply | Reported | Reality |
|---|---|---|
| `python` block + `js` block, both closed | `opened 1, closed 2` | 1 js close |
| `python` + `python` + **unclosed** `js` | `opened 1, closed 2` | **0 js closes** |
| bare fence + **unclosed** `js` | `opened 1, closed 2` | **0 js closes** |
| `python` + **unclosed** `js` | `opened 1, closed 1` | 0 js closes |

Rows 2 and 3 are the defect N-1 named, still live: `closed 2 > opened 1`, so the branch
reports `fence-present-but-block-unusable` — pointing the reader at a bad script when the
script is fine and the close is missing. The commit body writes this limit down as
"with a python block present ... 'opened 1, closed 1'" and calls the counts equal. They are
equal only for exactly one non-js block. At two, the arithmetic masks the missing close again.

The root cause is the same one as N-1: `closes` is not attributed to a block. A close is only
a close *of the js block* if the open fence it terminates is a js one.

## F2 — `test_a_python_block_is_not_a_close` pins the wrong number

`test_l3_script_path.py:995` asserts `"closed 2"` for `PY_THEN_JS`. That reply has one js
close; `2` is the count of all bare fence lines. The test's docstring says "there is exactly
one js close" and then asserts 2 — the assertion contradicts its own explanation, and would
have to change to make F1's fix correct.

## Suggested fix (executed, not sketched)

Walk the fences and attribute each close to the block it terminates:

```python
state = None; js_closes = 0
for m in re.finditer(r"```([^\n]*)", text):
    tag = m.group(1).strip().lower()
    if state is None:
        state = "js" if tag in ("js", "javascript") else "other"
    else:
        if state == "js":
            js_closes += 1
        state = None
```

Every row above then reports the true js close count (1, 0, 0, 0), and the two cases the
commit's own tests care about keep their wording. `js_closes < opens_js` becomes a sound
missing-close test with no equal-counts caveat.
