## (1) The specification says what true nearest-K needs

  position at refresh time, `dx*dx + dy*dy + dz*dz`, "Integer, no square root,

counter keeps the K nearest the far corner.

## N-1 (non-blocking) — one arithmetic imprecision worth fixing in code

`:206-208` says "up to **1331 integer distance computations** per refresh for
the worst-case cube (fewer when air is skipped earlier, which it is not — air is
tested inside the loop at `:904`)". The parenthetical is right — air is tested
inside the innermost loop, so the loop visits all 1331 cells — but if the
distance is computed for every cell *before* the air test, that is 1331
computations; if it is computed only for non-air candidates (which is what "per
non-air candidate" at `:196` says), it is the non-air count, which is at most
1331 and typically far fewer. The two sentences describe different quantities.
Compute the distance after the air test in the code and both read correctly; it
is also cheaper. Not blocking — the bound is still sound either way.
