for the case it was written for, but the guard it introduces fires on a case it
was not written for: on a bot with no active goal, an ordinary quiet script now
yields a goal that does not exist, once every 5 ticks, forever, and clears the
live plan doing it.

## Defect 3 — the idle re-poll bound: the mechanism is right, its scope is not

The bound itself is real and covered. Disabling the predicate:

    sed -i '3348s/return ticks >= SCRIPT_IDLE_MAX/return False/' agent/agent.py
    FAIL: test_an_idle_script_yields_its_goal_at_the_bound
    FAIL: test_the_idle_yield_names_the_bound_and_the_goal
    Ran 110 tests / FAILED (failures=2)

Two reds, both named. So the mechanism is pinned.

The **value** of `SCRIPT_IDLE_MAX` is not pinned: setting it to 500 leaves all
110 green, because every test loops `for _ in range(self.agent_mod.SCRIPT_IDLE_MAX)`
and asserts at the same symbol — the constant cancels on both sides. That is a
tuning choice, not a defect, and I am not filing it as one. It is noted so the
next reader does not mistake that survivor for a hole.

### F-1 (blocking): the guard fires with no goal, and clears the plan

`_script_idle_bound` is reached from `_run_script_tick` on the
`return False` path, above any test for whether a goal exists. The yield then
runs `_yield_script_to_planner`, which clears `_plan_steps`.

Driven directly, no goal set, a script that dispatches nothing:

    ticks=100, yields=20, goals=[]

Twenty yields in 100 ticks on a plan-less, goal-less bot — every 5 ticks,
indefinitely. And the clear is visible:

    steps before: ['mine']
    steps after:  []
    logged: "yielding goal (... while its goal was unfinished)"

The log line is false twice over: there is no goal, and the
"while its goal was unfinished" clause describes a goal that never existed.
Meanwhile the live plan (`['mine']`) is wiped by a script that was merely quiet.

**Why this is reachable.** `_unbind_planner_script` returns False for a script
bound from `bindings.json` — a hand-written script survives a planner yield by
design. And `_script_goal_hold` is only cleared when the goal ends. So for a
hand-written script under no goal, nothing unbinds it, nothing holds it, and the
idle run accumulates to the bound on every pass.

**Fix direction.** Gate the idle yield on an active goal — the same condition the
user-facing sentence already assumes. A bot with no goal has nothing to yield;
the idle log line is the right output there. And the log text should not name a
goal unless one exists; `while its goal was unfinished` should only be printed
when a goal is in fact unfinished.

**Not a finding, but worth a look while in here:** the same silent dispatch path
means a hand-written script that is legitimately waiting (a long walk, a poll
that has not yet produced anything) can reach the bound. The docstring argues an
intermittently-dispatching script never trips it, which is fair for a script that
acts, and is exactly why the no-goal case is the one that matters: it never acts
and never stops.
