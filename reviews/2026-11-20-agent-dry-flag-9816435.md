## The fix

`test/dry.test.mjs` test 5 is the right shape:

1. A **live** tick remembers `LIVE_BLOB` — seeding live memory is what makes a
   leak observable at all, since an empty live memory would report null either way.
2. The **dry** tick remembers a *different* `DRY_BLOB`, and the test asserts both
   `dry.memory_out != LIVE_BLOB` **and** `dry.memory_out == DRY_BLOB`. The pair
   is what makes it a positive: a dry tick that silently returned nothing would
   fail the second assertion, so "not the live blob" cannot pass vacuously.
3. A trailing live tick proves the worker still remembers after a dry tick.

The builder's note that they got the per-tick semantics wrong twice before
asserting the right property checks out: `memoryOut` is reset per tick
(`binding.js:113`), set at `:314`, read at `:383` / `worker.js:125`, and encoded
once at the wire boundary. "The live blob survives the next live tick" would
have tested the wrong thing.
