## 1. The pin as a pairing — PASS

Measured with `git show <rev>:agent/agent.py | grep -c '^def bound_script_path'`:

| rev | module-level `def bound_script_path` | `def _bound_script_path(self)` |
|---|---|---|
| `3887e79` | **0** | 1 (`:2667`) |
| `3230926` | **1** (`:3783`) | 1 |

The row's own command (`grep -c 'def bound_script_path'`) returns 0/1 and gets
the pairing right, but it is worth naming *why* it is right, because the pattern
is ambiguous: `3887e79` is not missing the capability, it is missing the
*module-level door*. It has the instance method the whole time. The plan says so
itself at `:1172-1173`. A reader who takes "3887e79 does not define
bound_script_path" at face value will think the resolver was absent, which is
wrong. The fix is still correct — `agent.bound_script_path("Scout")` is an
attribute access on the module and would have raised `AttributeError` — but the
commit message and §8.3.1d should say *module-level door*, not *the function*.

The `agent/` delta between the two pins is exactly two commits, both belonging:

```
83c6883 agent: module-level bound_script_path door for the run plan
3230926 review 3981e92: close both holds
```

Clean and minimal. `3887e79` is an ancestor of `3230926` (`merge-base
--is-ancestor` → YES), so the pin is a forward move on one line.

**The door's own body is right.** `3230926:agent/agent.py:3783` builds
`BotRunner.__new__(BotRunner)`, sets `.name`, and **delegates** to
`_bound_script_path()`. It does not reimplement the resolution, so the plan's
one-liner and the live tick cannot disagree. That was the substance of my
earlier hold and it is settled.

in tree at `3981e92` that mentions `83c6883`/`3981e92` is

**(c) "no holds" is contradicted by the next commit's own subject.** `3230926`
is titled *"review 3981e92: close both holds"*. A rev that exists to close two
holds cannot be introduced as the head with none — that sentence describes the
state *after* `3230926` under the name of the state *before* it.

**Why this is a defect and not a tidy-up.** This cell is the provenance an
operator reads at deploy time to answer "is this image reviewed?". The honest

true, and which is a **different sentence from the one written**. The

must be re-checked together whenever either moves. The pairing it did not
re-check is the one between the pin and its *citation*: the pin moved from
`3887e79` to `3230926` and the review cited beside it did not move with it.

**The pin is not in doubt.** `3230926` does close both holds — the commit adds

not a reason to re-pin.
