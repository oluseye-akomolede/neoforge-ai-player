# Design — script say dedupe

## 1. Where the memory lives, and why

**One `ScriptSayGuard` object per bot, held on the `BotRunner`, consulted in
`_deliver_script_deliveries` (`agent/agent.py:3019`).**

The three candidate homes, and why this one:

| home | rejected because |
|---|---|
| the runner (`binding.js`, as the row body suggested) | the runner is an isolation boundary; its job is "did the script ask to say this". Repeat-suppression is a product judgement about what bots read as, needs the recipient for `send`, and would become a runner contract every future script author must know. Also cannot see the `api.chat` path the `say` is finally delivered through. |
| the script (tell it the last line, let it decide) | the script is generated by the planner; asking it to remember its own last line makes every generated script responsible for a product rule, and a script that does not do it re-introduces the bug. |
| the agent, at the delivery loop | **chosen.** Every script `say`/`send` passes through one loop, the delivery record already carries `call`, `text`, `to`, and the `say` is delivered through `api.chat` here. The decision sits where the product lives and the runner is untouched. |

The guard is created once per bot, beside `ResultSlot`, and therefore survives
`agent.reset()` for the same reason — it is about the bot's chat presence, not
about the current goal. It does not survive a process restart, which is
correct: a restarted bot may well say the same thing again, and the first line
after a restart is the one a player would expect to see.

## 2. The rule, exactly

State: one record per key, holding the monotonic time that key was last
delivered and a `logged` flag saying whether the current window's suppression
has already been logged. Both fields live in the same record, so the flag
cannot drift from the window it describes; when a delivery moves the timestamp
past the window, the same write clears the flag.

- `say` stream key: `("say", text)`.
- `send` stream key: `("send", to, text)`.

On each delivery:

1. Compute the key for the call.
2. Look up the last delivery for **that same key**.
3. If it exists and `now - then < 60.0` s → **suppressed**. Count it always;
   log only if the record's `logged` flag is false, and set that flag in the
   same record.
4. Otherwise deliver, then record `(key -> now, logged=False)`.

The lookup is keyed, not "the last line overall": two bots' streams, and the
`say` and `send` streams, are independent, and `send("A", "go")` must not
suppress `say("go")`. The comparison is on the **key**, so alternating `A`/`B`
suppresses both after their first delivery each (spec scenario "Alternating
lines do not defeat the rule"), which "compare to the previous line" would not.

**The window is `now - then < 60.0`.** At exactly 60.0 s it is delivered, which
matches "after 60s quiet it is heard again". `now` is a monotonic clock injected
at construction (`time.monotonic` by default), so a wall-clock jump cannot
suppress or release a line early — the same discipline as `ResultSlot`.

**Nothing expires.** A key older than 60 s simply compares false and is
overwritten by the new delivery. No sweep, no timer, no background work.

## 3. Interactions with what already exists

- **The 30/min cap** (`binding.js:96`) is unchanged and still the rate limit.
  The dedupe removes repeated *content*; a script saying twelve different lines
  in a minute is delivered in full. The note at `agent/agent.py:3028-3031` (do not
  add a second limiter) is therefore not contradicted, and its docstring is
  updated to say dedupe is what is being added and why that is not a limiter.
- **The delivery contract** — "a delivered `say` or `send` counts toward the
  tick having handled it" — is preserved: a suppressed call still counts as
  handled, because the script did produce output and did not fail. It counts as
  *suppressed*, a distinct result in the return value, so the log can tell
  "nothing to say" from "said it already".
- **Dry ticks** already deliver nothing (`_deliver_script_deliveries` is fed
  `last_deliveries`, which a dry tick clears), so they neither read nor write
  the memory by construction; a test pins that they do not.
- **A sandbox recycle** restarts the runner's window but not this memory: the
  memory is in the agent. So a recycled sandbox still cannot make the bot
  repeat itself within the minute.

## 4. The prompt guidance line

`SCRIPT_SURFACE` (shared by both prompts) gains one line:

> `api.say` only when something changes (found, done, failed); never post the
> same status every tick.

`SCRIPT_SURFACE` holds **single** braces after the `fd5416b` fix, and it is not
run through `.format`. The gate is the existing test that the rendered prompt
contains no `{{` or `}}`; this line adds no braces, and that gate must stay
green with the line present. The count of `{{`/`}}` in the rendered prompt is
zero before and after.

## 5. Tests

Bounded, local, `nice -n 19`, at most 2 workers, `-B` for every mutant run.

Agent (`agent/test_agent_script_branch.py`, driving `_deliver_script_deliveries`
with an injected clock):

- same text within 60 s suppressed; different text delivered;
- same text at 61 s delivered;
- `send` keyed on `(to, text)`: same text to a second bot delivered;
- A/B alternation suppresses both after the first each;
- one log line per key per window, not one per tick;
- a suppressed-only tick still counts as handled and is not a refusal;
- a dry tick does not change the memory.

Prompt:

- the rendered `SCRIPT_SURFACE` in both prompts names the "only when something
  changes" guidance;
- still no `{{` or `}}`.

Each test gets one mutant that reds it: the window comparison flipped to `<=`
(or removed), the key ignoring `to`, the key ignoring `text`, the per-tick log,
and the memory cleared on dry tick.

## 6. Archive ordering

This change carries a MODIFIED delta on `bot-coded-agents`, a capability that
does not exist in `openspec/specs/` yet — it is created by `ai-written-scripts`
(15 requirements) and `coded-agents` (23 requirements). `validate --strict`
accepts the delta (rc=0); the refusal is INFO and lands only at archive time.

**Requirement: `ai-written-scripts` or `coded-agents` MUST archive before
`script-say-dedupe`.** If this change archives first, `openspec archive`
refuses it ("target spec does not exist; only ADDED requirements are allowed
for new specs") and the order must be corrected rather than the delta
rewritten. All three changes describe the same capability with compatible
text, so either creator archiving first makes this MODIFIED appliable as
written.

## 7. What this change does not do

- No runner change.
- No change to the 30/min cap.
- No rewrite of a suppressed line.
- No deploy, no pod exec, nothing in ci.
