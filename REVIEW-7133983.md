### My first mutant was narrower than theirs, and the count differed

I removed only the per-line `print(f"... log: {text}")` and got **3 red**, not 5.
I nearly wrote that down as a discrepancy. It is not: removing one statement
leaves the `+N more lines` and `runner dropped` prints alive, so the two reports

gives exactly 5. Both numbers are true about different mutants; theirs is the

described by what it removes, not by its name.

## The property that actually matters

Reverting the wire relay in `script_client.py` — restoring the exact pre-fix
behaviour — reddens **5** tests. So the suite now catches the original defect,
which is precisely what it could not do at M3-1b.

One caveat I checked rather than assumed: all five of those tests are **new in
this commit** (`present_at_parent=0` for each). Code and tests arrived together,
which is honest and normal. But "the suite catches it" is true going forward
only; the defect lived in a window no test could see — the same shape as the
stale ConfigMap one row ago. Worth stating because a green suite over an
unwatched file is the failure mode, not the reassurance.

## The two design points, checked

**Flood guard vs correctness bound.** The 5-line/200-char caps do report when
they bite (`+N more lines`, truncation with `…`), and the runner's own
`logs_dropped` is surfaced on a separate line. That separation is the important
one: a silent truncation reads exactly like a script that logged less than it
did, which is the dropped-line defect one layer up.

**Stale lines cannot be reprinted.** `last_logs`/`last_logs_dropped` are cleared
as the first statements of `tick()`. I checked the ordering directly: the only
thing preceding the clear is the docstring, and the first early return
(`if not self._source`) comes after it. There is no raise path before the clear.
The values are set on the SCRIPT path only, so a fallback tick carries nothing
from the previous tick. `test_a_stale_log_line_is_not_reprinted_as_this_ticks`
pins it.

**Defensive read.** `logs` non-list → `[]`; `logs_dropped` non-int → 0. The
`isinstance(dropped, bool)` exclusion is the detail usually missed, since `True`
is an `int` in Python. Losing log lines is survivable; losing the tick is not,
and the code takes that direction.

**Rate limit is wall-clock.** `time.monotonic()`, not a tick count, so the 60s
floor holds regardless of tick rate. Correct choice.
